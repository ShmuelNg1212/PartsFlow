## Decisions made inside this plan (routine, reversible)

- Demo data lives in a separate shop with `is_demo = true` and a "Demo shop" label. A user switches between shops in the shell. Live shop data never mixes with demo rows (R-DEMO-1).
- Database tests use Vitest + `pg` against a scratch database in local PostgreSQL, with a Supabase shim (study §2.1). No pgTAP.
- A cached `product_balances` table plus a reconcile view (R-DATA-2).
- Idempotency comes from a locked document row plus a client key (study §4.3).
- `supabase/config.toml`: `auto_expose_new_tables = false` and `enable_signup = false` (R-ROLE-2). These apply to a local stack only. The hosted project still needs public sign-up turned off in the dashboard (wizard step at rendezvous). Migrations revoke all client grants and grant only what is needed, so they are correct under the hosted auto-expose default as well. The shim copies that default.
- Migrations are files in `supabase/migrations/`. Each file is applied to the hosted project through the Supabase MCP `apply_migration` with the same name.
- `suggest_products` confidence (R-PROD-5, study §4.5): a part-number match is confident only when the brand also matches and no other product shares the normalized part number. A shared part number stays ambiguous even when the invoice names a brand.
- Duplicate check (R-POST-9) ignores reversed documents, so the D4 correction flow (reverse, then post a corrected copy of the same invoice) works.
- Error codes from the ledger functions: `42501` not permitted, `PF001` insufficient stock, `PF002` likely duplicate, `PF003` line not ready, `55000` wrong status. Details are JSON in the error `detail`.
- Phase 1 migrations are applied to the hosted dev project through MCP (2026-10-18). Hosted order differs from file order (post_document went last after a first attempt was declined for a `truncate`; the function now keeps its work in a jsonb array). There is no dependency between those two files.
- Hosted security advisor: 7 WARN "signed-in users can execute SECURITY DEFINER function". Accepted: post/reverse/opening/import are the API and check the owner role inside; `is_member`, `is_owner`, `document_file_access` reveal only the caller's own access. Performance advisor: composite foreign keys without covering indexes. Accepted at pilot size; revisit with real data.
- Icons: Phosphor, replacing shadcn's Lucide default (design ban list).
- Package versions follow study §3 after a docs check. Any pin-back is recorded here with the reason.
- Pin-back: TypeScript 6.0.3, not 7.0.2. typescript-eslint 8.71 supports `typescript <6.1` only. `baseUrl` is removed (deprecated in 6.0); `paths` works without it.
- shadcn/ui: CLI 4.22, preset `radix-nova`, `iconLibrary: phosphor`. It brings the `cn` package (shadcn-ui/cn) in place of clsx + tailwind-merge. `lucide-react` is removed.

### Phase 1. Database: schema, RLS, posting (the core rules)

- [x] **T1.1 Schema and RLS.** `tests: first`
  - Tables from study §4.1, `numeric` types from study §4.2, RLS on every table (R-DATA-5), membership helpers `is_member(shop)`, `is_owner(shop)`.
  - Status check: `draft | posted | reversed`. Trigger blocks edits to non-draft documents and their lines, and blocks client status changes (R-DATA-7, R-POST-10).
  - Raw extracted values in separate columns from corrected values (R-DOC-4).
  - Tests: outsider sees no rows; staff cannot write products; no client can insert into `stock_movements`, `product_balances`, or `audit_events`; client cannot set `status = 'posted'`; posted document lines cannot be edited.
  - Done when: these tests pass and every table has RLS enabled (a test lists tables with `relrowsecurity = false` and expects none).
- [x] **T1.2 Opening quantity and product import functions.** `tests: first`
  - `set_opening_quantity`, `import_products(jsonb)` (study §4.4). Audit events (R-DATA-8).
  - Tests: opening writes one `opening` movement and the balance; second opening on a product with movements fails; staff call fails; an import with one invalid row writes nothing.
- [x] **T1.3 `post_document`.** `tests: first`
  - Study §4.3 steps 1–6. Supplier alias save on post (R-DOC-8).
  - Tests (names cite rule IDs):
    - R-POST-1: a saved draft with lines leaves the balance unchanged.
    - R-POST-3/5: receive 5 → balance +5 exactly; one movement per line; status and movements commit together (force a failure on line 2 and check nothing commits).
    - R-POST-4/5: sell 2 → balance −2 exactly.
    - R-POST-6: post twice with the same key → balance changes once; two concurrent post calls on one document (two connections) → balance changes once.
    - R-POST-7: stock 3, two concurrent sales of 2 each → one succeeds, one fails, balance 1, never negative.
    - R-POST-8: insufficient sale fails; the error names product, on hand, requested.
    - R-POST-9: same number + counterparty + direction blocks; same file hash blocks; owner override with reason passes and writes an audit event; staff override fails.
    - R-POST-11: unit differs and no factor → fails; factor 10 on 2 boxes → +20.
    - R-DOC-6: a line with no confirmed product fails.
    - R-ROLE-1: staff and outsider calls fail.
  - Done when: all tests pass and the reconcile view shows zero differences after the suite.
- [x] **T1.4 `reverse_document`.** `tests: first`
  - Tests: R-POST-10 reversal restores the balance before the post; compensating movements link to the originals; reason required; reversing twice fails; reversal of a receipt whose stock is sold fails with the R-POST-8 style message (D5); staff fails.
- [x] **T1.5 Storage policies.** `tests: first`

  - Tests (shim `storage.objects`): outsider and anon cannot select or insert objects under another shop's path. Real-Supabase check of signed URL access goes to rendezvous (Q1).
- [x] **T1.6 Match suggestions.** `tests: first`
