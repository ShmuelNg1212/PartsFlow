## Decisions made inside this plan (routine, reversible)

- Demo data lives in a separate shop with `is_demo = true` and a "Demo shop" label. A user switches between shops in the shell. Live shop data never mixes with demo rows (R-DEMO-1).
- Database tests use Vitest + `pg` against a scratch database in local PostgreSQL, with a Supabase shim (study §2.1). No pgTAP.
- A cached `product_balances` table plus a reconcile view (R-DATA-2).
- Idempotency comes from a locked document row plus a client key (study §4.3).
- `supabase/config.toml`: `auto_expose_new_tables = false` and `enable_signup = false` (R-ROLE-2). These apply to a local stack only. The hosted project still needs public sign-up turned off in the dashboard (wizard step at rendezvous). Migrations revoke all client grants and grant only what is needed, so they are correct under the hosted auto-expose default as well. The shim copies that default.
- Migrations are files in `supabase/migrations/`. Apply them to the hosted project with `node scripts/apply-migration.mjs <files>` (one transaction per file, recorded in `supabase_migrations.schema_migrations` by name). The MCP `apply_migration` declines statements it treats as destructive (`truncate`, `drop`, `delete` in a function body), so the script is the default path (human decision, 2026-10-18).
- `SUPABASE_DB_URL` must be the Session pooler string. The direct host is IPv6-only and this machine has no IPv6 route.
- `suggest_products` confidence (R-PROD-5, study §4.5): a part-number match is confident only when the brand also matches and no other product shares the normalized part number. A shared part number stays ambiguous even when the invoice names a brand.
- Duplicate check (R-POST-9) ignores reversed documents, so the D4 correction flow (reverse, then post a corrected copy of the same invoice) works.
- Error codes from the ledger functions: `42501` not permitted, `PF001` insufficient stock, `PF002` likely duplicate, `PF003` line not ready, `55000` wrong status. Details are JSON in the error `detail`.
- Phase 1 migrations are applied to the hosted dev project through MCP (2026-10-18). Hosted order differs from file order (post_document went last after a first attempt was declined for a `truncate`; the function now keeps its work in a jsonb array). There is no dependency between those two files.
- Hosted security advisor: 7 WARN "signed-in users can execute SECURITY DEFINER function". Accepted: post/reverse/opening/import are the API and check the owner role inside; `is_member`, `is_owner`, `document_file_access` reveal only the caller's own access. Performance advisor: composite foreign keys without covering indexes. Accepted at pilot size; revisit with real data.
- Phase 2 server additions (not in the study): `product_stock` view and `search_products` (low-stock flag, alias search, text decimals); `save_draft(document, expected_updated_at, header, lines)` saves a whole draft in one transaction, keeps raw values, and refuses a stale save with `PF004`.
- A new draft opens with one blank line. Blank new lines are not saved and do not count as unsaved changes.
- E2E tests run against the hosted dev project with two seeded users and an "E2E test shop" (`node scripts/seed-dev-users.mjs`; credentials only in `.env.local`). Each run adds uniquely named products and documents to that shop.
- T3.2: `invite-member` is deployed with `verify_jwt = false` and checks the caller's session with Auth itself; it reads `SUPABASE_SECRET_KEYS` (falls back to the legacy service role key). An existing account is added without a new invite. Invited users land on `/set-password`. Not verified yet: a real invite email. Human steps before the pilot: set the hosted Auth Site URL and redirect URLs to the app origin, configure custom SMTP (the default sender only reaches project team addresses), and set the function secret `APP_ORIGINS` for each deployed origin.
- Members cannot be removed or have their role changed in the app yet; nothing in the spec asks for it.
- T3.4: exports live on Settings for every member (members can already read this data). Times are UTC ISO strings. Text cells that start with `= + - @` get a leading apostrophe so spreadsheets do not run them as formulas; decimal columns are never changed.
- T4.2/T5.1 overlap: the synthetic catalog and the three sample invoices (`scripts/demo-data.mjs`, `scripts/make-sample-invoices.mjs`, `public/samples/`) were made in Phase 4, because the demo extractor needs fixed files to match. Re-rendering changes the PDF hash (creation date), so the committed files and `demo-fixtures.ts` must change together. Some demo fields are set to low confidence or missing on purpose, to show R-DOC-5 marks.
- T4.3: `apply_extraction` (service role only) stores the server-computed hash, raw values, and the full result; it pre-fills empty corrected fields with clean values only, never the received quantity, and adds lines only to a draft without lines. `extract-document` is deployed with `verify_jwt = false` and checks the session itself; Azure is used only when `AZURE_DOCINTEL_ENDPOINT` and `AZURE_DOCINTEL_KEY` are set.
- T4.4: Azure's invoice schema (2024-11-30) has no line discount field; discount stays empty for Azure. The evaluation script (`node scripts/eval-extraction.ts <folder>`) is written and tested but not run: no credentials and no real invoices (Q2). Azure evaluation status: not done.
- T4.1: the new-document dialog asks for the direction, then "Take a photo" (phones, `capture="environment"`), "Choose a photo or PDF", or "Enter the lines by hand". A draft without a file can attach one later; attaching is blocked while the draft has unsaved edits, so extracted lines are never lost to a later save.
- T4.5: the line editor switches between table and cards by its container width (`@container`), so it fits beside the document viewer. Deviation: the phone flow shows all line cards in one scroll (document preview collapsed at the top), not one line at a time. The design pass (T7.2) can revisit it.
- Bug found by the Phase 4 browser tests and fixed: posting a draft with unsaved edits saved it first but kept the old version stamp; when the post was refused (duplicate, stock), the retry failed with "someone else saved". The workspace now adopts the saved version before it posts. `e2e/reverse-duplicate.spec.ts` covers it on every run.
- Icons: Phosphor, replacing shadcn's Lucide default (design ban list).
- Package versions follow study §3 after a docs check. Any pin-back is recorded here with the reason.
- Pin-back: TypeScript 6.0.3, not 7.0.2. typescript-eslint 8.71 supports `typescript <6.1` only. `baseUrl` is removed (deprecated in 6.0); `paths` works without it.
- shadcn/ui: CLI 4.22, preset `radix-nova`, `iconLibrary: phosphor`. It brings the `cn` package (shadcn-ui/cn) in place of clsx + tailwind-merge. `lucide-react` is removed.

### Phase 6. Pilot measurement

- [x] **T6.1 Measurement events.** `tests: first` Record per document: time from first open to post, number of corrected fields (corrected ≠ raw), number of match changes after a suggestion. Stored in `audit_events`. An owner CSV export of these metrics. No computed claims in the UI.
  - Done 2026-10-18. Migration `20261018100000_measurement.sql` (applied to hosted dev). `record_document_opened` writes one `document.opened` event per draft; the workspace calls it on open. Tests: `test/db/measurement.test.ts` (11), `e2e/measurement.spec.ts`.
  - Decision: "corrected" compares 4 header fields (number, date, counterparty, total) when extraction is done, and 6 fields per line that still has raw values (description, part number, quantity, unit, price, discount).   - Decision: "match change after a suggestion" = a line where the picker had a top suggestion when the user picked, and the final product differs. This value comes from the client; it is measurement data only and never affects stock.

Review-fix decisions (2026-10-18):
- Clear the query cache before an account change renders. Include the user ID in membership keys.
- Require the active shop ID for product and document reads. Shop selection returns home and resets the route subtree.

- Lock the parent document before the line guard checks draft status. Direct API line writes can receive a safe deadlock cancellation; the app uses the parent-first save RPC. See the wiki footgun.
- Serialize first-open measurement calls with the document lock. A regression test reproduced two events before the fix and one after it.
- Add discount entry and raw-value review on both layouts. The manual-flow test saves, reloads, and checks `1.25` exactly.
- Migration `20261018110000_rendezvous_posting_locks.sql` is applied to hosted development. The CLI created its file; its timestamp was advanced to sort after the earlier measurement migration.
