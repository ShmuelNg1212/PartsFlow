# Study: motion pass

Date: 2026-10-18. Mode: design. Skills: `find-animation-opportunities`, `minimalist-ui` (direction rules).

## 1. Question

Where does PartsFlow need motion? Where must it stay still?

## 2. Constraints from earlier decisions

- Pilot study §5 sets the visual direction. It bans scroll-entry animations, staggered reveals, and ambient motion on data screens. Motion is limited to short state feedback (150–200 ms, opacity and transform). It respects `prefers-reduced-motion`.
- The `minimalist-ui` skill asks for scroll entry, stagger, and ambient blobs. Pilot study §5 overrides these rules for this app. This study keeps that override.
- `src/index.css` already turns off popover, select, and dropdown animations. These open many times per document. Keep them off.
- Users are shop staff who enter stock all day. Daily use argues for less motion.

| Surface | Today |

| Phone bottom navigation | No press feedback. Gap. |
| Lines editor | A new line appears with no bridge. Gap. |

## 4. Opportunities that pass the gate

Each candidate passed four checks: frequency, purpose, speed, and function.

New tokens in `src/index.css` `:root`:

- `--ease-out: cubic-bezier(0.23, 1, 0.32, 1)`
- `--ease-in-out: cubic-bezier(0.77, 0, 0.175, 1)`

The dialog rule moves to `var(--ease-out)`. The two curves are close; the change is not visible.

Reduced motion: the global 0.01 ms rule stays. All new entrances become instant under that preference. This keeps one rule for the whole app.

## 5. Rejected candidates

- Route and page transitions. Rejected: core navigation, tens of times per day, on data screens.
- Skeleton-to-content fade. Rejected: TanStack Query serves cached data on most visits, so the fade would play on every navigation.
- Picker, select, and dropdown entrances. Rejected: the product picker opens once per line, many times per day. Kept off by earlier decision.
- Celebration after posting. Rejected: owners post many times per day. The toast "Posted. Stock is updated." is enough.
- Collapse animation for the phone document viewer. Rejected: it animates a 60dvh panel that holds a PDF or image. The cost is high and the benefit is low.
- Hold-to-confirm for delete draft and reverse. Rejected: both already have a confirm step. A hold adds a second guard and slows owners.
- Save status text ("Saving…", "All changes saved"). Rejected: high frequency. A text swap reads well.
- Staggered list reveals and scroll entry from `minimalist-ui`. Rejected: banned by pilot study §5.

## 6. Verdict

PartsFlow is close to right. The base components already animate correctly. The gaps are small: inline alerts and step changes that teleport, one snapping press, and one weak progress indicator. Item 1 has the highest leverage, because one shared class covers about twenty surfaces. The whole pass is CSS plus class names. No motion library is needed.
